📚 Qu'est-ce qu'un SVM ?

Le Support Vector Machine (SVM) est un algorithme de classification supervisée qui cherche l'hyperplan optimal séparant deux classes de données. L'objectif est de maximiser la marge, c'est-à-dire la distance entre l'hyperplan et les points les plus proches de chaque classe.

Les points les plus proches de l'hyperplan sont appelés vecteurs de support ?. Ce sont les seuls points qui influencent la position de l'hyperplan !

🎯 Concept Clé : La Marge Maximale

Le SVM cherche l'hyperplan avec la plus grande marge possible. Une grande marge signifie une meilleure généralisation sur des données nouvelles.

Équation de l'hyperplan :
w · x + b = 0

où :
• w = vecteur normal (perpendiculaire à l'hyperplan)
• x = point dans l'espace
• b = biais (intercept)
Les marges sont définies par :
w · x + b = +1 (marge positive - classe +1)
w · x + b = -1 (marge négative - classe -1)

Largeur de la marge : 2 / ||w||

🔄 Le Kernel Trick (Astuce du Noyau)

Pour les données non-linéairement séparables, le SVM utilise des noyaux (kernels) pour projeter les données dans un espace de dimension supérieure où elles deviennent séparables.

Noyaux courants :

1. Linéaire : K(x, y) = x · y
→ Pour données déjà séparables

2. RBF (Radial Basis Function) :
K(x, y) = exp(-γ ||x - y||²)
→ Pour motifs complexes et non-linéaires

3. Polynômial : K(x, y) = (x · y + c)^d
→ Pour frontières courbes

⚖️ Le Paramètre C

Le paramètre C contrôle le compromis entre :
• C faible : Marge large, tolère quelques erreurs (moins de surapprentissage)
• C élevé : Marge stricte, essaie de classifier tous les points correctement (risque de surapprentissage)

💡 Analyse SWOT du SVM

✅ Avantages

  • Très efficace en haute dimension
  • Robuste au surapprentissage (avec bon C)
  • Kernel trick = versatilité incroyable
  • Fonctionne bien avec peu de données
  • Garantie mathématique de solution optimale
  • Mémoire efficace (stocke seulement les SV)

⚠️ Inconvénients

  • Lent sur très grands datasets (>100k points)
  • Sensible au choix des hyperparamètres
  • Pas de probabilités natives (seulement classes)
  • Difficile à interpréter avec kernels non-linéaires
  • Sensible aux données non-normalisées
  • Classes déséquilibrées = problématique

🎯 Cas d'Usage Idéaux

  • Classification de textes (spam, sentiments)
  • Reconnaissance d'images (visages, objets)
  • Bioinformatique (classification de protéines)
  • Détection d'anomalies (One-Class SVM)
  • Données avec frontières complexes
  • Quand peu de données disponibles

🚫 Pièges à Éviter

  • Ne pas normaliser les données = désastre
  • C trop élevé = surapprentissage garanti
  • Ignorer la validation croisée pour C et γ
  • Utiliser sur millions de points = lenteur
  • Classes très déséquilibrées sans ajustement
  • Oublier de tester plusieurs kernels

🏭 Conseils Production

Prétraitement obligatoire :

  • ✅ Normaliser/standardiser toutes les features (StandardScaler)
  • ✅ Gérer les valeurs manquantes avant
  • ✅ Encoder les variables catégorielles

Optimisation des hyperparamètres :

  • ✅ Grid Search ou Random Search pour C et γ
  • ✅ Validation croisée (5-fold minimum)
  • ✅ Tester plusieurs kernels (linear, rbf, poly)

En production :

  • ✅ Limiter à <100k points ou utiliser SGDClassifier
  • ✅ Sauvegarder le modèle ET le scaler
  • ✅ Monitorer la distribution des données (drift)
  • ✅ Considérer LinearSVC pour très grands volumes
