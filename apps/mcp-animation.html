📖 Comprendre le MCP

🎯 Objectif

Standardiser la communication entre les applications IA et les sources de contexte (fichiers, APIs, bases de données, etc.).

⚡ Avantages

• Architecture modulaire
• Interopérabilité
• Sécurité renforcée
• Extensibilité

🔧 Les trois primitives

📚 Resources

Données statiques ou dynamiques que le serveur expose (fichiers, URLs, contenus de base de données).

🛠️ Tools

Fonctions que le LLM peut appeler pour effectuer des actions (exécution de code, écriture de fichiers).

💭 Prompts

Templates pré-configurés avec instructions et contexte pour guider le LLM.

🔄 Flux de communication

  1. Connexion: Le client se connecte au serveur MCP (stdio, SSE, ou HTTP)
  2. Découverte: Le client interroge les capacités du serveur (resources, tools, prompts disponibles)
  3. Requête: Le client envoie une requête JSON-RPC pour accéder à une resource ou exécuter un tool
  4. Traitement: Le serveur traite la requête et accède aux données/services nécessaires
  5. Réponse: Le serveur retourne les résultats au format JSON-RPC structuré
  6. Utilisation: Le client (ou le LLM) utilise le contexte obtenu pour générer une réponse

💡 Cas d'usage

  • IDE Integration: Accès au code, système de fichiers, git
  • Database Access: Requêtes SQL, lecture de schémas
  • API Integration: Connexion à des services externes (Slack, GitHub, etc.)
  • Knowledge Bases: Accès à des documentations, wikis internes

✅ Avantages

  • Standard ouvert Anthropic: Interopérabilité entre différents LLMs et outils
  • Intégration facile outils/données: Plugin system simple pour exposer APIs
  • Sécurité contrôlée: Permissions granulaires, sandbox par ressource
  • Extensible: Créer vos propres servers MCP en quelques lignes
  • Découplage: LLM indépendant des sources de données (swap provider facilement)

⚠️ Limites

  • Standard récent (adoption): Lancé fin 2023, écosystème encore jeune
  • Latence réseau: Chaque tool call = aller-retour serveur MCP
  • Complexité setup serveur: Déployer/maintenir plusieurs MCP servers
  • Debugging difficile: Erreurs distribuées entre client, serveur, LLM
  • Pas de caching natif: Requêtes répétées peuvent être coûteuses

💼 Cas d'Usage Production

  • LLM + bases de données: Claude/GPT peut requêter Postgres, MongoDB sans code custom
  • LLM + APIs internes: CRM, ERP, ticketing (Salesforce, Jira, ServiceNow)
  • Workflows multi-outils: "Analyse les tickets Jira, résume dans Slack, update Confluence"
  • Agents autonomes: Agent qui peut lire emails, créer tasks, scheduler meetings
  • Code assistants: Accès git, CI/CD, logs, metrics pour debugging contextuel

🚨 Pièges à Éviter

  • Pas de fallback si serveur down: Implémenter retry logic + circuit breakers
  • Sécurité mal configurée: MCP server avec accès DB sans auth = faille critique
  • Tools mal documentés: LLM ne sait pas quand/comment utiliser si description vague
  • Trop de tools exposés: LLM confus avec 50+ tools. Limiter à 10-15 pertinents
  • Pas de rate limiting: LLM peut spammer API si mal prompté
  • Ignorer les coûts: Chaque tool call = tokens input/output facturés

🎯 Production 2025

📚 Stack Recommandé

  • MCP SDK (TypeScript): Official Anthropic SDK pour créer servers
  • FastMCP (Python): Wrapper simplifié pour créer MCP servers rapidement
  • LangChain Tools: Convertir tools LangChain en MCP servers
  • Claude Desktop: Client officiel avec support MCP intégré

🏢 Providers & Clients

  • Claude (Anthropic): Support natif MCP via API & Desktop app
  • OpenAI GPT-4: Via function calling (adaptateur MCP → OpenAI tools)
  • VS Code / Cursor: Extensions MCP pour code assistants
  • Zed Editor: Integration MCP native pour AI collaboration

🔓 MCP Servers Open-Source

  • Filesystem MCP: Accès fichiers locaux avec permissions
  • PostgreSQL MCP: Requêtes SQL read-only sécurisées
  • GitHub MCP: Issues, PRs, commits, code search
  • Google Drive MCP: Search & read documents cloud
  • Community: 100+ servers sur modelcontextprotocol.io/servers
