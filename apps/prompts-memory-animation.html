📖 Architecture de Contexte dans les LLMs

⚙️ 1. Prompt Système (System Prompt)

Instructions permanentes qui définissent le comportement de base de l'IA.

Caractéristiques :

  • Invisible pour l'utilisateur : Défini par les développeurs
  • Priorité maximale : Guide tout le comportement du modèle
  • Exemples d'usage :
    • Définir le rôle : "Tu es un expert en programmation Python"
    • Contraintes : "Ne jamais donner de conseils médicaux"
    • Style : "Réponds toujours de manière concise et professionnelle"
    • Format : "Utilise toujours des puces et des exemples"

💡 Astuce : Le prompt système est fixe pour toute la session. C'est la "personnalité" de base de l'IA.

📚 2. Mémoire / Historique (Conversation History)

Liste chronologique de tous les échanges précédents dans la conversation.

Fonctionnement :

  • Structure : Alternance de messages USER et ASSISTANT
  • Contexte cumulatif : Chaque nouveau message s'ajoute à l'historique
  • Limitation : Fenêtre de contexte limitée (4k-128k tokens selon le modèle)
    • GPT-3.5 : 4k tokens (~3k mots)
    • GPT-4 : 8k-32k tokens
    • Claude 3 : 200k tokens
    • Gemini 1.5 : jusqu'à 1M tokens
  • Gestion : Quand la limite est atteinte, les messages les plus anciens sont supprimés (ou résumés)

💡 Astuce : La mémoire permet au LLM de comprendre le contexte ("Combien d'habitants ?" → Il sait qu'on parle de Paris grâce à l'historique).

👤 3. Prompt Utilisateur (User Prompt)

Le message actuel de l'utilisateur qui déclenche la génération d'une réponse.

Techniques de Prompt Engineering :

  • Clarté : Soyez précis et spécifique dans vos demandes
  • Contexte : Fournissez les informations pertinentes
  • Format : Spécifiez le format de réponse souhaité
    • "Liste à puces de 5 points"
    • "Tableau comparatif"
    • "Code Python avec commentaires"
  • Few-shot learning : Donnez des exemples
    • "Traduis comme dans ces exemples : dog→chien, cat→chat, bird→?"
  • Chain-of-thought : "Explique ton raisonnement étape par étape"

🧠 4. Le LLM - Traitement et Génération

Le modèle combine les 3 sources pour générer une réponse cohérente.

Processus de génération :

  1. Tokenization : Découpe le texte en tokens (morceaux de mots)
  2. Embeddings : Convertit les tokens en vecteurs numériques
  3. Attention mechanism : Le modèle "fait attention" aux parties pertinentes du contexte
    • Prompt système → instructions permanentes
    • Historique → contexte de la conversation
    • Question actuelle → ce qu'il faut répondre
  4. Génération autoregressive : Produit la réponse token par token
  5. Sampling : Utilise beam search ou temperature pour choisir les tokens

🔢 Gestion du contexte :

Contexte_Total = System_Prompt + Σ(Messages_Historique) + User_Prompt

Exemple : 50 (système) + 120 (historique) + 10 (question) = 180 tokens en entrée
Limite max : variable selon le modèle (4k à 1M tokens)
Réponse générée : ~40 tokens qui seront ajoutés à l'historique pour le prochain tour

💡 Cas d'Usage Pratiques

🤖 ChatGPT / Assistant conversationnel

Système : "Tu es ChatGPT, un assistant IA créé par OpenAI..."
Mémoire : Les 10-20 derniers échanges de la conversation
User : Question actuelle de l'utilisateur
Résultat : Réponse contextuelle qui tient compte de toute la conversation

📝 Rédaction d'article

Système : "Tu es un rédacteur professionnel. Style journalistique, factuel."
Mémoire : Plan de l'article, sections déjà rédigées
User : "Rédige la section 3 sur les causes du changement climatique"
Résultat : Section cohérente avec le reste de l'article

💻 Copilot de Code

Système : "Tu es un expert en programmation. Commente ton code."
Mémoire : Fichier actuel, imports, fonctions déjà définies
User : "# Fonction pour calculer la moyenne" (commentaire → complétion)
Résultat : Code cohérent avec le contexte du fichier

⚠️ Limites et Considérations

  • Fenêtre de contexte limitée : Au-delà de la limite, les anciens messages sont perdus
  • Coût proportionnel : Plus de contexte = plus de tokens = coût plus élevé ($)
  • Latence : Plus de contexte = génération plus lente
  • Prompt injection : Risque de sécurité si l'utilisateur essaie de "hacker" le prompt système
  • Hallucinations : Le LLM peut inventer des informations s'il manque de contexte
  • Pas de vraie mémoire : Le modèle ne "se souvient" pas entre sessions (sauf si historique sauvegardé)
