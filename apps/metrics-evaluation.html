🎓 Comprendre les Métriques ML

Matrice de Confusion

La matrice de confusion est l'outil fondamental pour évaluer un classifieur binaire. Elle compare les prédictions du modèle avec les vraies valeurs.

Vrais Positifs (TP): Correctement prédit comme positif
Vrais Négatifs (TN): Correctement prédit comme négatif
Faux Positifs (FP): Erreur Type I - Prédit positif mais réellement négatif
Faux Négatifs (FN): Erreur Type II - Prédit négatif mais réellement positif

Métriques Dérivées

Accuracy (Précision globale): (TP + TN) / Total
→ Bon pour classes équilibrées

Precision (Précision): TP / (TP + FP)
→ "Parmi les prédictions positives, combien sont correctes?"
→ Important quand FP est coûteux (ex: spam, diagnostic médical)

Recall/Sensitivity (Rappel/Sensibilité): TP / (TP + FN)
→ "Parmi les vrais positifs, combien sont détectés?"
→ Important quand FN est coûteux (ex: détection de fraude, maladie grave)

F1-Score: 2 × (Precision × Recall) / (Precision + Recall)
→ Moyenne harmonique de Precision et Recall
→ Idéal pour classes déséquilibrées

Specificity (Spécificité): TN / (TN + FP)
→ "Parmi les vrais négatifs, combien sont correctement identifiés?"

ROC & AUC

La courbe ROC (Receiver Operating Characteristic) trace TPR (sensibilité) vs FPR pour différents seuils de classification. AUC (Area Under Curve) résume la performance.

AUC = 1.0: Classificateur parfait
AUC = 0.9-0.99: Excellent
AUC = 0.8-0.9: Bon
AUC = 0.7-0.8: Acceptable
AUC = 0.5: Aléatoire (pas mieux qu'un tirage à pile ou face)
AUC < 0.5: Pire qu'aléatoire (inversez les prédictions!)

Classes Déséquilibrées

Dans beaucoup de problèmes réels, les classes sont déséquilibrées (ex: fraude 0.1%, email spam 10%). L'accuracy seule est trompeuse!

Exemple: Si 1% sont frauduleux, un modèle qui prédit "pas fraude" pour TOUT aura 99% accuracy mais sera inutile!

Solutions: Utilisez F1-Score, Balanced Accuracy, Cohen's Kappa, ou AUPRC (Precision-Recall curve).

Sensibilité aux Outliers

Les valeurs extrêmes peuvent fortement impacter certaines métriques :

• MSE (Mean Squared Error): Très sensible aux outliers (erreurs au carré)
• MAE (Mean Absolute Error): Moins sensible
• Huber Loss: Compromis entre MSE et MAE

📊 Analyse SWOT - Métriques & Évaluation

✅ Avantages

  • Évite les mauvaises métriques (accuracy sur données déséquilibrées)
  • ROC/AUC robuste pour comparaison de modèles
  • Matrice de confusion visuelle et interprétable
  • Trade-offs explicites entre métriques (precision vs recall)
  • Permet de choisir selon les coûts métier (FP vs FN)

⚠️ Limites

  • Pas de métrique universelle pour tous les problèmes
  • Trade-offs toujours présents (precision vs recall)
  • Business metrics peuvent différer des métriques ML
  • Métriques peuvent être trompeuses sur classes déséquilibrées
  • Nécessite compréhension du contexte métier

🎯 Cas d'Usage

  • ML en production: Monitoring performances continues
  • A/B tests: Comparaison de variantes de modèles
  • Model selection: Choix du meilleur algorithme
  • Monitoring dérive: Détection dégradation performances
  • Reporting: Communication avec parties prenantes

🚨 Pièges à Éviter

  • Accuracy aveugle: Ne regarder que l'accuracy globale
  • Ignorer déséquilibre: Ne pas adapter les métriques
  • Mauvaise métrique: Optimiser une métrique non alignée avec le business
  • Pas de validation croisée: Surestimer les performances
  • Oublier les outliers: Impact sur MSE et autres métriques
