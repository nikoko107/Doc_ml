📊 Analyse SWOT - Prétraitement de Données

✅ Avantages

  • 80% du succès ML dépend de la qualité des données
  • Normalisation critique pour SVM, réseaux de neurones, K-means
  • Outliers détectables et gérables (IQR, Z-score)
  • Améliore vitesse et convergence des algorithmes
  • Permet de traiter features à échelles différentes

⚠️ Limites

  • Perte d'information possible lors de l'imputation
  • Biais introduits selon méthode de nettoyage
  • Pas de recette unique (dépend des données et du problème)
  • Coûteux en temps (exploration, décisions, pipeline)
  • Risque de data leakage si mal fait

🎯 Cas d'Usage

  • Pipeline production: Transformation automatique des nouvelles données
  • Feature engineering: Création de nouvelles variables
  • Data augmentation: Génération de données synthétiques
  • Nettoyage: Gestion valeurs manquantes, outliers, doublons
  • Standardisation: Mise à l'échelle pour algorithmes sensibles

🚨 Pièges à Éviter

  • Scaling après split: DATA LEAKAGE! Toujours normaliser après train/test split
  • Imputation naïve: Remplacer par moyenne sans analyse
  • Ignorer outliers: Ne pas détecter valeurs aberrantes
  • Pas de pipeline reproductible: Transformations manuelles non automatisées
  • Oublier normalisation test: Utiliser mêmes paramètres que train

⚡ Bonnes Pratiques Essentielles

  1. Toujours fit() sur train, transform() sur train ET test:
    scaler.fit(X_train) # Apprendre paramètres sur train uniquement
    X_train_scaled = scaler.transform(X_train)
    X_test_scaled = scaler.transform(X_test) # Appliquer mêmes paramètres
  2. Détecter outliers AVANT normalisation: IQR, Z-score, isolation forest
  3. Pipelines sklearn: Automatiser toutes les étapes pour reproductibilité
  4. Sauvegarder transformations: Pickle/joblib pour utiliser en production
  5. Validation croisée: Pipeline complet dans chaque fold
