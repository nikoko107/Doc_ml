🎓 Pourquoi le Prétraitement est Crucial ?

En Machine Learning, "Garbage in, garbage out". Le prétraitement peut faire la différence entre un modèle qui fonctionne à 60% ou 95% de précision.

1. Détection des Outliers

Méthode IQR (Interquartile Range) IQR = Q3 - Q1 (Quartile 3 - Quartile 1) Outlier si : • X < Q1 - 1.5 × IQR (trop petit) • X > Q3 + 1.5 × IQR (trop grand) Pourquoi 1.5 ? → Convention statistique : capture ~99.3% des données normales → Balance entre sensibilité et spécificité

Types d'outliers :

• Erreurs de saisie : Prix = 5€ au lieu de 500 000€ → À SUPPRIMER
• Valeurs extrêmes légitimes : Penthouse à 5M€ → À GARDER ou transformer
• Anomalies intéressantes : Fraude bancaire → C'est ce qu'on cherche !

2. Impact des Outliers sur KNN

Le K-Nearest Neighbors classe un point selon ses 3 plus proches voisins. Les outliers faussent les distances et créent des prédictions aberrantes.

Exemple concret : Maison de 100m² → Prix ? AVEC outliers (erreur : maison 500m² à 50k€) : → KNN trouve cette erreur comme voisin proche → Prédiction : 120k€ (trop bas à cause de l'outlier) SANS outliers : → KNN utilise uniquement les vraies données → Prédiction : 250k€ (correct !) Différence : 130k€ d'erreur à cause d'UN seul outlier !

3. Normalisation pour KNN

Problème d'échelle : Maison A : (Superficie: 100m², Chambres: 3) Maison B : (Superficie: 120m², Chambres: 4) Distance SANS normalisation : → √((120-100)² + (4-3)²) = √(400 + 1) = 20.02 → La superficie domine complètement ! Distance AVEC normalisation [0,1] : → Superficie: 100m² → 0.5 | 120m² → 0.6 → Chambres: 3 → 0.5 | 4 → 0.75 → √((0.6-0.5)² + (0.75-0.5)²) = 0.27 → Les deux features contribuent équitablement Min-Max Scaling : X_norm = (X - X_min) / (X_max - X_min) → Ramène toutes les features sur [0, 1] → Essentiel pour KNN, SVM, réseaux neurones

4. Pipeline de Prétraitement

Ordre recommandé en Production : 1. Exploration des données (EDA) → Histogrammes, box plots, statistiques 2. Gestion des valeurs manquantes → Imputation par moyenne/médiane ou suppression 3. Détection et traitement des outliers → IQR, Z-score, visualisation 4. Feature engineering → Créer nouvelles features (ex: prix/m²) 5. Encodage des catégories → One-hot encoding, label encoding 6. ⚠️ SPLIT train/test → AVANT normalisation ! 7. Normalisation → fit() sur train, transform() sur train ET test 8. Entraînement du modèle

Erreur fréquente (Data Leakage) :

❌ FAUX : Normaliser AVANT split train/test
→ Le modèle "voit" les statistiques du test pendant l'entraînement
→ Performance optimiste mais fausse !

✅ CORRECT : Split d'abord, puis normaliser
→ Calculer min/max/mean UNIQUEMENT sur train
→ Appliquer ces mêmes valeurs sur test
→ Performance réaliste

5. Quand Normaliser ?

• OBLIGATOIRE : KNN, SVM, Réseaux de neurones, Régression régularisée (Ridge, Lasso)
• RECOMMANDÉ : PCA, Clustering (K-means), Gradient Descent
• PAS NÉCESSAIRE : Arbres de décision, Random Forest, XGBoost

Pourquoi ? Les arbres font des splits sur des valeurs absolues, pas des distances.

Applications Entreprise

• Immobilier : Détecter les erreurs de saisie dans les prix
• Finance : Identifier les transactions frauduleuses (outliers intentionnels)
• E-commerce : Normaliser prix, poids, dimensions pour recommandations
• Industrie : Détecter les défauts machines (capteurs anormaux)
