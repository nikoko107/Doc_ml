📖 Comprendre le RAG

🎯 Objectif

Améliorer les réponses d'un LLM en lui fournissant des informations pertinentes extraites d'une base de connaissances externe.

⚡ Avantages

• Réponses basées sur des sources fiables
• Informations à jour
• Réduction des hallucinations
• Traçabilité des sources

🔄 Processus

  1. Vectorisation de la question: Transformation de la question en vecteur numérique
  2. Recherche de similarité: Calcul de la distance entre le vecteur question et les vecteurs documents
  3. Récupération: Extraction des top-k documents les plus pertinents
  4. Augmentation du prompt: Ajout du contexte récupéré à la question originale
  5. Génération: Le LLM génère une réponse basée sur le contexte fourni

✅ Avantages

  • Connaissances à jour sans ré-entraînement: Ajoutez des documents sans modifier le modèle
  • Réponses factuelles avec sources: Citations traçables, réduction des hallucinations
  • Coût faible vs fine-tuning: Pas besoin de GPUs pour entraîner, juste indexation
  • Domaine privé: Intégrer des connaissances propriétaires sans les exposer
  • Explicabilité: On sait exactement d'où viennent les informations

⚠️ Limites

  • Qualité dépend du retrieval: Si la recherche rate les bons docs, la réponse sera mauvaise
  • Latence ajoutée: Embedding + recherche vectorielle + génération = plus lent
  • Chunking difficile: Découper des docs longs sans perdre le contexte est un art
  • Hallucinations possibles: Si retrieval échoue, le LLM peut inventer
  • Limite de contexte: Top-k docs doivent tenir dans la fenêtre du LLM

💼 Cas d'Usage Production

  • Chatbots documentation: Support technique avec docs produit à jour
  • Q&A entreprise: Recherche dans bases de connaissances internes (Confluence, SharePoint)
  • Assistants avec connaissances privées: Legal, médical, finance
  • Fact-checking: Vérification d'informations avec sources vérifiées
  • Recherche sémantique: "Trouve-moi tout sur les contrats 2024" sans mots-clés exacts

🚨 Pièges à Éviter

  • Embedding model inadapté: Utiliser text-embedding-ada-002 pour du code = mauvais. Préférer models spécialisés (code-search-ada)
  • Chunk size mal choisi: Trop petit = contexte perdu. Trop grand = bruit. Sweet spot: 512-1024 tokens avec overlap 128
  • Pas de reranking: Top-k cosinus ≠ top-k pertinents. Ajouter un reranker (Cohere, cross-encoder)
  • Qualité base vectorielle ignorée: Garbage in = garbage out. Nettoyer vos docs avant indexation
  • Pas de fallback: Si retrieval rate, avoir un plan B (question générique au LLM + disclaimer)

🎯 Production 2025

📚 Stack Recommandé

  • LangChain: Orchestration RAG, chaînes complexes, agents
  • LlamaIndex: Spécialisé RAG, meilleur pour indexation avancée
  • Haystack: Production-ready, pipeline modulaire, monitoring
  • Vector DBs: Pinecone (managed), Qdrant (open-source), Weaviate, Milvus

🏢 Providers (Embeddings + LLM)

  • OpenAI: text-embedding-3-large (3072 dim) + GPT-4 Turbo
  • Anthropic: Voyage embeddings + Claude 3.5 Sonnet
  • Cohere: embed-v3 multilingue + Command-R+ (128k context)
  • Google: Vertex AI embeddings + Gemini 1.5 Pro (1M context!)

🔓 Open-Source Alternatives

  • Embeddings: sentence-transformers (all-MiniLM-L6-v2, mpnet), instructor-xl, e5-large-v2
  • LLM: Llama 3 70B, Mixtral 8x7B, Qwen 72B (via Ollama, vLLM)
  • Stack complet: Qdrant + sentence-transformers + LlamaIndex + Llama.cpp
  • Reranker: cross-encoder/ms-marco-MiniLM-L6-v2
